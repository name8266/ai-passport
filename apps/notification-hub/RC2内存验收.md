# Passport 通知中心 Public RC2：内存与负载验收

> 适用：ESP32-C3 / 8 MB Flash / 无 PSRAM。RC2 重构了 NimBLE、Wi-Fi/Web 生命周期、声音工作线程和运行时内存监控。下面的指标是现场验收门槛，**不是云端模拟得出的设备实测结果**。

## 诊断日志

通过串口工具采集完整启动及运行日志。ESP-IDF 已安装时可在正确固件项目目录执行：

```bash
idf.py -p "<串口>" monitor
```

或者使用能以正确串口参数打开设备的串口终端。每 30 秒会记录：

- `stable/runtime: internal_heap=...`：此刻可用的内部 8 位堆字节数。**这是判断当前余量的主要依据**。
- `min_since_boot=...`：启动以来历史最低水位。即使早期瞬间只有 200 B，随后线程释放了栈空间，这个数仍可能一直保持 200 B；**不能把它当成当前余量**。
- `largest=...`：当前最大连续可分配块，HTTPS/TLS 分配最重要的指标之一。
- `stack_margin=...`：当前运行日志线程的栈剩余空间，不能代替其他任务的栈余量。
- `Web deferred` / `Rejecting Web RAM exhaustion`：内存保护拒绝管理平台启动，通知捕获优先保留。
- `Deferring TLS`：AI 被延迟而不是在低堆内存下继续分配。

## 请提供以下五组数据

| 场景 | 实际操作 | 记录 |
| --- | --- | --- |
| A. 冷启动稳定态 | 上电 60 秒，尚未连接热点 | 最后两条 stable/runtime、after BLE |
| B. iPhone 已配对 | 蓝牙连接、正常接收通知 5 分钟 | stable/runtime、BLE 断开/重连次数 |
| C. 管理入口 | 长按确认进入设置，连接热点、打开网页 | Web 启动前、Web 启动后与网页内 RAM 指标 |
| D. 内存回收 | 返回通知界面，关闭网页，等待超过 2 分钟 | `after Wi-Fi/Web release`、其后 stable/runtime |
| E. AI 与通知突发 | 配置客户自有 API 后产生 3 条真实通知、查看摘要 | TLS 之前、after AI window、失败日志 |

首次未配网的设备会自动启动热点；已经配网但 AI 关闭的设备则是**按需启动**。AI 开启时，设备保留联网能力以便自动总结。

## 资源保护规则

| 操作 | 启动前最低内部空闲堆 | 启动前最大连续块 |
| --- | ---: | ---: |
| Web 管理入口 | 40 KB | 16 KB |
| 直接 HTTPS / TLS | 48 KB | 20 KB |

Web 启动后的额外保护底线：至少 **16 KB** 内部空闲堆以及至少 **4 KB** 最大连续块，低于任一门槛立即回滚管理服务。设备全部工作期间应避免出现持续低于 16 KB 的稳定堆空闲状态。

**建议的负载扩展目标：** BLE+本地存档稳定态空闲 ≥48 KB、最大连续块 ≥20 KB；24 小时持续接收真实 ANCS 事件时，不应有持续下降的空闲堆曲线。未达到目标就不要继续增加常驻功能。这个目标必须现场测量才能确认。

## 重要行为与失败处理

1. 首次设置热点因内存不足无法启动时，**不要一直反复重启清空设备**；保存串口日志，优先排查 BLE/RAM 静态占用、Web 启动失败及硬件型号。
2. 管理页打开后若无操作，离开设置模式 2 分钟后可能自动断开；再次进入设置页面即可重新唤醒。
3. 提示音默认关闭，用户开启后分配额外工作线程；首次配对和大量通知期间应分别测试开启/关闭提示音的空闲堆。
4. 内存保护能延后 AI/Web，但不保证 Flash 满盘、BLE 接收队列溢出时绝对不丢通知。
5. **Bluedroid→NimBLE 迁移需要真实 iPhone 验证。** 请重点检查安全配对、旧债券重连、数据特征订阅、系统通知和 Service Changed。
6. 断电时不能把未验证的 FAT FS 双槽写入等同于完整数据库事务；重要记录仍需周期性备份。

## 装机评估

如果 C 场景虽然打开网页但当前堆低于 16 KB，或 D 场景关闭 Web/Wi-Fi 后空闲堆未明显恢复，判定内存回收尚未满足交付要求。将 A–E 场景日志交回进行针对性优化，**不要按“9.5 分完成版”对外宣称**。
