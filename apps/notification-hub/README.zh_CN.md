# Passport 通知中心 · Public 1.0.0 RC1

**交付状态：客户安装候选版。** 该版本已经纳入自动编译、协议/归档测试、ASan/UBSan 和发布包检查；iPhone 配对、断电及长期运行的真机验收由部署方进行。不能将“云端测试通过”解释为已完成硬件验收。

## 产品简介

Passport 通过 iPhone 的 Apple Notification Center Service (ANCS) 获取系统允许公开给配件的通知元数据、标题及有限预览，保存在设备 Flash 中，在 240×320 屏幕按应用查看，并在用户主动开启 AI 后通过设备自身 Wi-Fi/HTTPS 发送筛选后的新通知请求摘要。**不要求额外 iOS App、NAS、Mac 或云端自建网关。**

硬件规格：ESP32-C3、8 MB Flash、无 PSRAM、3 个物理按键。当前摘要最多保留 5 项结构化待办；每累计 3 条新通知触发一次摘要，已读清除摘要及上下文，关闭仅隐藏；网页可以逐项完成或重新显示摘要。

## 客户安装

请使用构建产物中真实中文命名的 **《客户安装说明.md》**。发布包提供全新设备合并镜像及保留数据的应用升级镜像，两者用途不同。**首次安装在确认不需要设备原数据之后才执行全片擦除。已有通知数据时禁止直接使用全片擦除。**

若已安装 Beta 18 / Beta 19，且分区和 Wear Levelling 均为 512 字节安全模式，可在备份后尝试仅更新应用分区；更早版本的旧存档格式可能与本版不兼容，**目前不提供自动数据迁移**。

## 首次开机

1. 手机在蓝牙设置中找到 **Notify Hub** 并完成配对、允许共享通知，按设备提示操作。
2. 连接 Passport 生成的 `PassportHub-XXXX` 热点，浏览器访问 `http://192.168.4.1/`。
3. 在 **设置** 中填入客户自己的 Wi-Fi SSID/密码、模型供应商的 HTTPS Endpoint、模型名和 API Key，保存后设备重启。
4. **AI 默认关闭**；只有用户启用并配置有效密钥后才发送筛选后的通知。默认服务商地址是 `https://api.deepseek.com/chat/completions`、模型为 `deepseek-flash`；这些只是可修改的服务默认值，**不是账户、测试密钥或预存用户数据**。
5. 没有示例通知、示例待办、预置 iPhone 配对记录、预置 Wi-Fi 密码或 API Key。设备存储内容取决于刷写前的 Flash 状态，因此全新交付必须按安装说明确认清空旧设备数据。

## 操作说明

| 操作 | 作用 |
| --- | --- |
| 通知页上下键 | 浏览通知 |
| 通知页确认键 | 查看通知详情 |
| 通知页长按上键 | 查看最新摘要 |
| 摘要页确认键 | 已读清除整份摘要和待办 |
| 摘要页长按确认键 | 只关闭当前显示，保留上下文 |
| 网页「完成」 | 单独结束一个结构化待办 |
| 网页「重新显示」 | 重新打开已经隐藏的摘要 |
| 网页「立即总结」 | 手动请求处理，仍要求 AI 已开启 |
| 设置页 | 配网、API、亮度、声音、保留期 |

### 设备限制

- iOS 并不保证 ANCS 永远存在或发送所有通知；正文可能被截断、隐藏或根本不提供。ANCS 的删除事件并不等于微信等 App 的“撤回”。
- 结构化待办已满 5 项时暂停 AI 自动处理，**原通知先保留**；处理器和 Flash 容量仍有上限，高峰队列或满盘仍可能丢通知，网页会显示告警。
- 归档仅对已完成摘要提交的记录执行到期清理；还未汇总的记录可能长期占据 Flash。已处理原通知也可能暂留到下一次批量 GC；物理删除不是安全擦除。
- 模型可能遗漏或误解一条新通知。已有结构化待办由本地程序管理，但这不等于模型首次提取的正确率达到 100%。
- **按本项目当前约定，设置热点无 Wi-Fi 密码，局域网管理也不要求登录。** 任何能够访问该网络的人可能查看通知或更改设置。该安全取舍由部署方接受，本版不声称解决管理鉴权问题。
- 通知、摘要、配置与密钥存储在设备 Flash；当前未启用完整的加密存储/安全启动交付链。不适用于未经风险评估的高敏感数据环境。
