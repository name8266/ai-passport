# FoloToy AI Passport 世界之窗

世界之窗是面向 ESP32-C3 AI Passport 的公开摄像机地图浏览器。**运行时已经改为 Passport 设备独立工作：只需要连接可访问互联网的 2.4 GHz Wi-Fi，不再需要电脑、树莓派、代理服务或局域网网关服务器。**

固件把维护目录中的 **825 个公开摄像机记录和 1020 个地图地点**直接编译进 8 MB Flash。Passport 自己访问发布方 HTTPS 图片地址，在设备内流式解码 JPEG、转换为 RGB565，再交给 LVGL 显示。

195 个国家的首都登记点中，目前 50 个找到公开来源，49 个在维护检查时成功取得图片。没有来源的地点继续明确标记，不伪造覆盖。

## 设备操作

| 操作 | 地图 | 画面观看 |
| --- | --- | --- |
| 前后键 | 选择地点 | 切换地点 |
| OK | 打开画面 | 刷新 |
| 长按 OK | Wi-Fi 设置 | 返回地图 |
| 长按上键 | 随机游览 | 随机游览 |
| 长按下键 | 全部地点 / 首都 | 切换全屏 |

观看时每 60 秒尝试刷新。界面显示“已获取”只表示 Passport 本次成功拿到图片，不代表发布方原始拍摄时间一定是当前时刻。

## 第一次联网

1. 启动 Passport。
2. 手机连接屏幕显示的 `WorldCam-XXXX` 热点，并输入屏幕上的随机密码。
3. 浏览器打开 `http://192.168.4.1`。
4. **只填写 2.4 GHz Wi-Fi 名称和密码**。
5. 连接成功后配置热点关闭，之后所有摄像机图片都由 Passport 自己联网获取。

网络配置保存在应用自己的 NVS 命名空间。旧版本可能留下的 `gateway` 键不再使用，在重新保存网络配置时会清除。

## 设备内直连架构

```text
Passport Wi-Fi → 发布方 HTTPS JPEG → 设备内流式解码 → RGB565 → LVGL
```

地点目录、中文名称、坐标和源 URL 都在固件 Flash 中。HTTPS 使用 ESP-IDF 根证书包。设备不会先把原始大图完整下载到 RAM，而是边从 TLS 连接读取、边解码；最终显示缓冲普通模式为 192×128，全屏为 240×160。

南极站有 1 个特殊来源先发布一个小型元数据文件，再给出真正 JPEG 文件名；这一步解析也已经搬到 Passport 内完成，不经过网关。

当前 JPEG 解码采用 1、1/2、1/4、1/8 离散缩放并居中显示，源图片比例不同时可能裁切边缘。当前解码器不支持渐进式 JPEG；遇到这类源会显示失败提示，不应导致界面崩溃。

## 构建与验证

使用 ESP-IDF 5.5.3：

```bash
./tools/validate.sh
```

ESP Component Manager 会解析 `jpeg_roi_decoder ^0.5.3`。验证流程会检查 Flash 目录是否与维护 JSON 一致、确认设备代码不再包含旧的网关 API 契约、执行主机测试、构建 ESP32-C3 固件并检查完整镜像布局。

仓库里的 `gateway/` **现在只保留为维护/审计工具和固件目录的数据源**。使用 WorldCam 不需要启动 `gateway/server.py`，它不再位于设备运行链路上。

## 当前限制

- 公开摄像机 URL 可能失效、重定向、更新证书、限制地区访问或改变图片格式。
- 中国大陆能否直连取决于实际网络和各发布方；维护检测工具只能测某个网络当时的结果，不能保证长期可用。
- 当前仍没有做到每个国家首都都有可用摄像机。
- 在把该分支视为正式硬件版本前，仍应进行 USB 真机烧录、内存峰值和长时间刷新验收。
